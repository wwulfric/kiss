KISS Skill Store

显式加载一个 skill，别把整个世界塞进上下文。

KISS 是面向 coding agent 的极简 skill store：先显式安装，再按名调用。 每次运行只把被点名的 SKILL.md 交给外层 agent，不替 agent 推理、执行脚本或调用模型。

查看 GitHub
agent-session 
$ kiss add vercel-labs/agent-skills --skill browser-test
installed browser-test

$ /kiss browser-test url=https://example.com

# KISS loaded skill: browser-test

## User invocation
- Skill: browser-test
- Args: "url=https://example.com"

## Skill instructions
...only this skill enters context

三步完成一次干净的 skill 调用

安装是管理动作，运行是上下文交接。KISS 不自动下载、不自动更新， 也不把未点名的 skill 带进本轮任务。

01

安装

明确给出 source 和 skill 名称。

kiss add owner/repo --skill browser-test
02

调用

在 agent 中按名触发。

/kiss browser-test url=https://example.com
03

交接

KISS 输出当前 skill 的 Markdown context。

kiss run browser-test url=https://example.com

边界窄，状态清楚，删除也干净

KISS 不试图成为另一个 agent runtime。它只保存 skill、记录来源、 加载被点名的入口 Markdown，并把上下文交还给调用方。

隔离存储
KISS 管理的 skill 位于 $KISS_HOME/skills。
单 skill 暴露
run 只读取当前被点名的 skill。
安装记录可审计
记录 source、resolved commit、sha256、skillFolderHash。
不接管执行
不执行 skill 脚本，不读取模型 key，不调用 provider。

KISS Store Agent native skills Project repo

把 `/kiss` 接到你的 agent

CLI 是稳定核心，bridge skill 保持很薄。先安装 KISS CLI，再用 kiss setup 写入当前 agent 可识别的 bridge skill。

macOS / Linux

curl -fsSL https://raw.githubusercontent.com/wwulfric/kiss/master/scripts/install.sh | bash

Windows PowerShell

irm https://raw.githubusercontent.com/wwulfric/kiss/master/scripts/install.ps1 | iex
Bridge skill kiss setup kiss setup --agent claude

从一个明确需要的 skill 开始。

安装、调用、审计、删除都保持显式。KISS 只负责把正确的上下文放到本轮任务里。
